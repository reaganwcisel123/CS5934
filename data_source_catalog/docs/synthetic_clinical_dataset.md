# Synthetic Clinical Dataset

Generated by `src/ingestion/synthetic_clinical.py`. Everything in it is
synthetic and non-PHI by construction.

## Why it exists

We need clinical-looking patient rows for dashboard development and prototype
modeling without touching real patient data. The roster is keyed by
`county_fips` and reproducible: rerunning the build gives the same patients.

## How it's generated

Each county gets 3-4 synthetic patients from a PRNG seeded with the county's
FIPS code (the same Mulberry32 generator the dashboard uses). A patient record
carries vitals (BP, A1c), an age, a recent visit date, and a social-needs
struggle. The preventable hospitalization flag isn't a coin flip; it's drawn
from a logit of A1c, systolic BP, and age plus seeded noise, so sicker
synthetic patients flag more often. During the dataset build the records are
joined with real county-level SDoH context (the `nb` neighborhood-burden
fields are filled from actual county domain scores).

## Provenance

The source's `provenance` is `synthetic` and its catalog entry
(`synthetic_clinical_dataset`) is classified `synthetic_non_phi`. Never treat
it as real patient data, and never commit real patient data in its place.
